# Security reporting

Do not post credentials, private recordings, or exploitable vulnerability details
in a public issue. If GitHub's **Security → Report a vulnerability** is available,
use it for a private advisory. If unavailable, open a public issue requesting a
private reporting channel without disclosing the vulnerability. No personal
security email is designated. Private-reporting availability is recorded in the
publication report; it must not be assumed enabled from this file alone.

The actively developed version is 0.5.1. There is no formal security support SLA.
Treat project JSON, media and SoundFonts as untrusted input; retain local backups.
